How it works

From request to result

  1. Search interface

    A user enters a request from a browser or chat application. Search matches the request to the agent built to handle it.

  2. Agent server

    The agent runs in a controlled runtime on the agent server. The server can be a single instance or a load-balanced cluster.

  3. Agent framework

    The framework executes the agent’s commands. The agent calls LLMs and enterprise systems and streams results.

  4. Search2o Cloud

    After the run, conversation state is encrypted and stored in Search2o Cloud. Follow-ups repeat the process.

How search works

Search uses natural-language descriptions written by developers to determine which agent is designed to produce the requested result. It supports major languages and returns matches in under a second.

hr_policy · description
Answers employee questions about Acme Corp workforce policies: vacation and leave, benefits eligibility, remote-work rules, expense limits and the code of conduct. It explains what the policy says and where to find the form. It cannot approve requests, change records or make exceptions.
Agent framework

JSON syntax, Python expressions

An agent is defined in JSON as a set of functions, each containing an ordered sequence of commands. Strings enclosed in { } are evaluated as Python expressions.

weather.json · agent definition
// JSON with comments (JSONC).
{
  "functions": {
    "main": {  // Execution begins here
      "commands": {
        "func": { "name": "forecast" },
        "prompt": {
          "user": "{ f'Forecast: {result}. {sys.query}' }"
          // After the above line, variable 'user' will have
          // the value of the f-string. 'user' can be used in
          // any subsequent expression.
        },
        "llm": { "profile": "anthropic", "streamOutput": true }
      }
    },
    "forecast": {
      "commands": {
        "api": { "url": "https://api.weather.gov/…/forecast" },
        // 'result' is a special variable that holds the result
        // of the last command that was run, in this case, the
        // api call above.
        "return": "{ result['properties']['periods'][:8] }"
      }
    }
  }
}
Platform

Built for the enterprise

Agent security

Agents can only call what's on your allowlist. Secrets come from your vault and never appear in an agent. Conversations and other sensitive information can be end-to-end encrypted.

Model neutrality

Bring your own keys. OpenAI, Anthropic, and Gemini models are supported out of the box, as is any LLM with a compatible interface. Other LLMs require only a small adapter class.

Chat integrations

Agents can be used from Slack, Microsoft Teams, and Google Chat. The agent server provides the required integration endpoints, and the documentation walks you through the setup.

Agent development

The agent editor provides code completion and contextual help. AI assist creates agent drafts from your prompts. Validation runs produce a full trace. Agents are versioned. Profiles keep models and prompts out of agent code.

API & automation

The agent server exposes a REST API described by an OpenAPI specification. Use it to run non-interactive agent workflows — scheduled, event-driven, or in batch. The bundled search UI uses the same API.

Access & roles

Four roles: Users run searches; developers build agents and manage the agent environment; administrators manage users, the system environment, and security; owners manage the account and billing.

Reports

What ran, what failed, what it cost

Four top-level reports show trends. Each row opens a detailed report for the corresponding agent or user.
