How a conversation works

Each agent in a conversation picks up the chain of LLM messages the previous agent left behind.

Conversation
Book my trip for Tuesday's all-day meeting in New York
DiscoverySearch matched the request to the Travel desk agent, and the UI ran it automatically. The request had no conversation ID, so a new, empty conversation started.
Travel desk UA1191 departs 06:00 Tuesday, back at 19:30, and a night at the Marriott near the office. $1,240. Book it? BookHold Submit
Human in the loopThe agent’s state is stored, and when the user answers, the agent continues from where it paused.
Travel deskBooked UA1191 and the hotel night. The confirmation is in your inbox.
Conversation contextThe Travel desk agent ended here, and the agent server saved the conversation context automatically: the agent’s variables and its prompts. A prompt is the chain of messages exchanged with an LLM, kept in the conversation in a standard format.
File the expenses for that trip
ReimbursementsFiled the New York trip, $1,240, against your cost center. Sent to your manager for approval.
Building on each otherThe request carried the conversation ID, so the agent server restored the saved context first. Search then matched the follow-up to the Reimbursements agent, which continued the same prompt exchange. To the LLM it looks like one continuous conversation.

How an agent is defined

Draft with AI and the schema‑aware code editor help you build an agent in minutes, just by describing it.

// A simple RAG agent that answers from a knowledge base.{
  "functions": {
    "main": {
      "commands": {
        "api": {
// The API profile 'knowledgeBase', defined externally, is used to connect.          "profile": "knowledgeBase",
          "queryParams": {
// The API query parameter is set to sys.query, a built-in variable that contains the user’s request.            "q": "{ sys.query }"
          }
        },
        "var": {
// A variable called 'passages' is set with a Python expression.          "passages": "{ [hit['text'] for hit in result[:5]] }"
        },
        "llm": {
// An LLM profile, 'gpt5_mini', is used. LLM profiles specify the vendor and the model in use.          "profile": "gpt5_mini",
// A prompt named 'answer' is used to talk to the LLM. This prompt is specific to this agent and defined externally.          "prompt": "answer",
          "streamOutput": true
        }
      }
    }
  }
}

An agent is defined in JSONC, JSON with comments. A string enclosed in braces is interpreted as a Python expression, evaluated in a controlled runtime.

An agent is a set of functions. main is a special function where every run starts. Each function contains a list of commands from the set shown below.

Enterprise features

Security & privacy

Secrets live in your vault. Conversations and memories are encrypted, by default or, optionally, end to end. Data privacy lists how each kind of data is handled.

Multi-user access

Four roles: users, developers, administrators and owners. Service accounts for bots and scripts. Built-in authentication as well as single sign‑on.

Source available

Everything that runs in your organization can be built from the source: the agent server and the UI. Set the logging configuration to see every call to the cloud.

Multiple environments

An agent refers to enterprise systems by profile name. Dev and prod profiles point at their own systems, so the same agent runs unchanged.

Horizontally scalable

Agent servers are stateless and can be run in a cluster. Configuration and profile changes are live on the next agent run on every server, without a restart.

Integration

Integrate at three levels: from Python expressions inside an agent, through the REST API, and with hooks that run your code at the server’s decision points.
