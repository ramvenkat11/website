Search2o is a platform for creating and running AI agents — behind one search box.

  • Search is the orchestration. A request is matched to the agent that handles it and executed. Any number of agents sit behind one search box.
  • Conversations span agents. A follow-up can go to a different agent, and agents can build on each other’s work.
  • Hybrid architecture. Stateless agent servers run on your side with no other infrastructure dependency; Search2o Cloud maintains state.

How it works

From request to result

  1. Type a request

    The user types a request — Search2o matches it to the agent built for it. The best match runs; a setting can offer the close matches as choices instead.

  2. The agent executes

    The agent runs on the agent server, next to your APIs, databases and documents.

  3. Reason, act, stream

    The agent reasons with LLMs, calls tools and enterprise systems, asks the user when it needs input, and streams its progress and answer as it goes.

  4. Context is encrypted and stored

    After the run, the conversation state is encrypted on the agent server and stored in Search2o Cloud — with end-to-end encryption, if you choose — ready for the next request.

Search

How does search find the right agent?

Search matches each request against the natural-language description of each agent, written by its developer. It supports most major languages, scales to thousands of agents, and returns matches within 300 ms. In our tests, the right agent ranked first about 85% of the time and appeared in the top three about 95% of the time, even with some overlapping descriptions.

Agent framework

JSON syntax, Python expressions

An agent is defined in JSON and contains a set of functions. Each function is an ordered dictionary of commands. Strings enclosed in { } are interpreted as Python expressions. Execution begins with the main function.

Platform

Built for the enterprise

Agent security

Agents run in a controlled runtime: only the functions on your allowlist can be called, and compile rules bound what an expression may do. Secrets come from your vault and never appear in an agent. Conversation state is encrypted before it leaves your server.

Model neutrality

Bring your own keys. OpenAI, Anthropic and Gemini are supported out of the box, and so is any LLM with an interface compatible with one of the three. For any other LLM, you write a small adapter class.

Profiles

LLMs, APIs, databases, MCP servers, and prompts are defined as named profiles that agents reference. This lets agents move from development to production without code changes, and lets shared configuration changes be made in one place for every agent that uses them.

Agent development

Agent editor provides code completion and context help. AI assist creates agent drafts from your prompts. Validation runs full trace. Agents are versioned and past versions are available for three months. Notifications post all agent and config changes.

API & automation

The agent server exposes a REST API described by an OpenAPI specification. The bundled UI is built entirely on it. Use it to build your own search UI, or to run non-interactive agent workflows — scheduled, event-driven, or in batch.

Access & roles

Four roles: owner, administrator, developer, user. Users run searches; developers build agents and control the agent environment; administrators manage users, the system environment and security; the owner alone has access to billing.

Reports

What ran, what failed, what it cost

Four top-level reports with trends. Each row opens a detailed report for that agent or user.
