Docs / Skill integration

Installing the skill

You need a Search2o account with published agents, an agent server the person's machine can reach, and an integration token for each person who will use the skill. The skill is published at github.com/Search2o/search2o-skill, and the same folder works in every client that implements the Agent Skills standard.

The folder

SKILL.md holds the steps described in What the skill does. reference.md is what the assistant reads for the details: the result codes and what to do with each, the output part types and the shape of a question. The script needs Python 3 and nothing else.

Authorization

The skill authenticates as the person, with an integration token: the same per-person, revocable token a chat bot uses. A token can search, run agents and manage that person's own conversations. It cannot read or change configuration, manage users or read reports, whatever the person's role. Runs made through the skill appear in the usage report under the person's name.

Each person creates a token from their profile in the GUI, as described in Connecting a person. The token is never stored in the skill's files. Please revoke a token when it is no longer needed, and revoke any token that has been pasted into a chat.

Trying it

Each call prints one JSON object. A failed call prints a message and exits with a non-zero status, so the assistant sees what went wrong: a refused token, a server it cannot reach, or a call the token may not make.

Where it works

Agent Skills is an open standard, published at agentskills.io, and the same folder works unmodified in every client that implements it — Claude Code, Cursor and OpenAI Codex among them.

The script calls your agent server over the network. In a client that runs on your machine, such as Claude Code or Cursor, the script uses the machine's network and reaches the agent server directly. In a client that runs scripts in a hosted environment, whether that environment can reach your agent server depends on the network settings of the client's account.

In Claude Code a skill can be distributed to a team through a plugin; other clients have their own ways, and the folder is the same in each.

Fitting it to your company

The description

The description in SKILL.md is the only thing the assistant reads to decide whether a request is for the company's agents. Too broad, and general requests go to search; too narrow, and requests that should reach an agent never do. It helps to edit its examples to name the kinds of work your agents do, then try a handful of requests that should use the skill and a handful that should not.

Tag scoping

search accepts a tag and returns only the agents that carry it. A company that wants narrower triggers can install two copies of the skill — one for support agents, one for finance agents — each with its own name, its own description, and instructions that pass its tag to search.

Long-running agents

The script waits for the agent to finish, for up to 600 seconds, the default of maxAgentRuntime, the runtime limit on how long an agent may run. If your account allows longer runs, raise TIMEOUT in the script to match.
