Docs / Agent runtime

The allowlist

The allowlist is the complete set of functions and objects that an agent's Python expressions may reach. Expressions have no builtins of their own: the allowlist takes the place of Python's builtins, so a name that is not on the allowlist does not exist for an agent. Developers edit the allowlist in the GUI under Guardrails, and the allowlist applies to every agent in the account.

How expressions are contained

Expressions are contained at the application level, not by the operating system. Four things decide what an expression may do: the allowlist decides which names the expression can reach; the compile rules decide which operators and which shapes of expression are accepted; the runtime limits bound a run in time, iterations, rows and LLM spend; and the scope rules below decide which variables are visible. The runtime does not limit memory or CPU. Rewriting an operator to a function of your own is the tool for operations that could load the server.

Entry forms

One entry per line. Anything after # is a comment, and blank lines are ignored. The server resolves an entry in one of three ways.

  • A single name is looked up among Python's builtins: len, str, int, sorted.
  • Two names, the first of which is a builtin type, give one method of that type: str.join, dict.items.
  • Any other dotted path is split at the last dot. The part before the dot is imported as a module, and the last name is read from that module: math.sqrt, json.loads, mycompany.vault.get_secret.
  • as gives the entry the name expressions use. Without an alias, expressions use the entry's full dotted name: json.loads(...), not loads(...).

A wildcard such as os.path.* is not an entry form and adds nothing. The last name in a dotted path may itself be a module. os.path, for example, makes every public function of os.path reachable. We would suggest listing the functions an agent needs, one by one, rather than the module that holds them.

What an entry makes reachable

  • The name itself, and every public member of the object behind the name. A class on the allowlist can be called to construct an object, and the object's public members can be used.
  • Private and dunder members are refused, even on an allowlisted object. Any name that starts with an underscore is refused, whether the name is a variable, an attribute, a function or a keyword argument.
  • import is not available in an expression. Everything an agent can use is imported by the allowlist.

The rules for what an expression may contain, beyond names, are listed in Compile rules.

Scope of an expression

An expression may reference only:

  • the names on the allowlist, with the public members of the objects behind them;
  • variables set earlier in the same function, and the function's arguments;
  • agent and conversation variables set earlier, as agent.x and conv.x;
  • the read-only sys and command namespaces. Which sys variables are present is decided in System variables.

No other variables, objects or runtime state are accessible. See Variables and namespaces.

Async functions

Expressions run on the agent server's shared event loop, so a function that blocks the loop must not be allowlisted. asyncio.run, time.sleep and synchronous network calls are examples. Async functions are welcome: when the whole expression is a call to an async function, the result is awaited automatically. Inside a larger expression, an async call must be awaited with await. See Awaiting.

Registering your own code

The allowlist is also where custom code enters the runtime. A package your agents need is installed next to search2o in the server's environment, on every agent server.

  • An LLM adapter: a class that extends LlmAdapter. When the allowlist is built, each such class is constructed once with no arguments, and a class that cannot be constructed is written to the server's log.
  • The key function for end-to-end encryption, named in the encryption settings.
  • A function that reads your own vault, called from expressions and from the dynamic strings of a profile.
  • A function that a Python operator is rewritten to.

When the allowlist changes

When the allowlist is saved, the agent server behind the GUI resolves every entry first. An entry that cannot be imported refuses the save, and the GUI shows which entries failed. Once saved, every agent server rebuilds the namespace before its next agent run, so the change is live everywhere without a restart; see How a change reaches every server. Each server imports each entry from its own Python environment. An entry that cannot be imported there is skipped, the message Error importing '...' is written to that server's log, and the remaining entries still load. A package present on one server and missing on another shows up this way, so it helps to keep the environments of your servers identical.
