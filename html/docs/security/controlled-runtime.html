The controlled runtime

Python expressions in agents execute inside a controlled runtime. Administrators decide what the runtime allows through the allowlist, operator remapping and runtime limits.

The runtime is controlled at the application level, not by the operating system. The runtime decides which names an expression can reach and which operations an expression may perform; the runtime does not limit memory or CPU. Operator remapping is the tool for operations that could overload the server.

Allowlist

The allowlist is the complete set of functions and objects available to expressions.

  • Any name not on the list cannot be referenced or called.
  • All public members of an allowlisted object are accessible.
  • Private members and dunder methods (__init__, __class__, …) are disallowed even on allowlisted objects.
  • import is not available. Everything an agent can use is imported by the allowlist.

The asyncio package itself cannot be put on the allowlist, because the package can interfere with the server's event loop. asyncio.gather and asyncio.sleep are always available as gather and sleep. gather is the way to run several async calls in parallel.

Every entry is checked against the server's Python environment at startup and whenever the allowlist changes. A failing entry is reported on the Agent servers page.

Operator remapping

Each potentially expensive Python operator can be allowed, denied, or rewritten to a safe function. The operators are + - * / // % ** << >> @. By default ** is rewritten to a bounded implementation, and the shift and matrix operators are denied. The safe functions are built in, but can be replaced with your own functions from the allowlist. See Compile rules. The rules are applied when a draft is validated or published.

Validation rules

The runtime enforces limits on resource usage and complexity. All limits are set in Runtime limits and Compile rules. The limits include:

  • maximum agent execution time,
  • maximum iterations of each loop,
  • maximum rows a database call may return,
  • maximum LLM spend per run,
  • maximum nesting depth of comprehensions, and maximum generators per comprehension, in one expression,
  • maximum length of an agent definition.

Scope of an expression

Within an agent, an expression may reference only:

  • functions on the allowlist, and allowlisted objects with their public members,
  • variables defined earlier in the same function,
  • agent and conversation variables defined earlier,
  • the read-only sys and command namespaces.

No other variables, objects or runtime state are accessible.
