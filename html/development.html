Agent development

An agent framework built for AI‑assisted development

Tactet has its own agent framework and a corresponding agent runtime. An agent is expressed in JSONC (JSON with comments), with Python expressions. There are 20 built‑in commands (or declarations) in JSON that cover all the aspects of agent programming. The entire framework is structured on a schema. Draft with AI, the code editor and validation work from that schema, in the development environment that is part of the UI.

Agent framework

An agent is JSON with Python expressions

Below is a complete agent. It searches a knowledge base for the user’s request and has a model write the answer from the best passages.

Every value keeps its JSON meaning, with one extension: a string enclosed in braces is a Python expression, evaluated when the agent runs. Any other string is plain text. Most strings are allowed to be a Python expression. The exceptions are function names, prompt names and a few others that are needed to check the agent for correctness at compile time. An expression can read variables, the result of the last command, and what the runtime provides, such as the user’s request. Each expression is checked when the agent is validated and runs in a controlled runtime.

Every agent has the same structure

An agent is a set of functions. Each function contains an ordered map of commands. The commands run in the order in which they are declared.

A command is a key, and its value contains the command’s fields: an object for most commands, and a single value for simple ones such as progress and trace. To use a command a second time in the same function, add a suffix after a dot: api, then api.2. The syntax and structure pages explain all the rules.

Every run starts in main. Another function runs when a function calls it with func or parallel, or when a model calls it as a tool.

A function can be a tool for the model

This agent answers questions about orders. Its function getOrder looks up one order through an API, and the model decides when to call it.

Systems and prompts are defined outside the agent

An agent names the systems it calls and the prompts it sends. The connection details are in platform-wide profiles, and the text of each prompt is in the agent’s meta. This agent lists a user’s open IT tickets and has a model say where each one stands.

A profile is shared by every agent that names it. A secret is read from the vault by name, so its value appears in neither the profile nor the agent. A prompt’s system and user text are written like any other string: plain text, or a Python expression that reads the agent’s variables.

The agent runtime handles everything the agent does not specify: credentials, connections to outside systems, streaming, conversation memory, pauses for a person’s answer, and the time and cost limits for every run.

Development environment

Draft, edit, validate, publish

The UI includes a complete development environment for agents. An agent goes through four steps before users can run it.

Draft with AI

Draft with AI writes or modifies an agent from a description of what the agent should do. It works from the same schema that the editor and validation use, and it knows the profiles and prompts of your account. It never sees your APIs and databases, so it leaves paths, queries and parameters empty, with a comment that says what belongs there.

Try the Draft with AI demo with your own description or one of the examples.

Edit

A draft is private to the developer who created it. The code editor is built on Monaco, the editor inside Visual Studio Code, and it understands the agent framework. It suggests the commands and fields allowed where you are typing, and it points out mistakes as you type.

Validate

Validation checks the definition against the schema and the security rules. It also confirms that everything the agent names exists in the account. The agent server then runs the draft against a sample question and shows the trace: every command that ran, the values it received, and what it returned. A draft cannot be published from the UI until it validates.

The Trace demo shows a trace of a running agent.

Publish

Publishing gives the agent a version and makes it ready to execute. But it cannot be matched by search until a description is created in plain English. Search indexes that description and makes the agent available to users. When several developers edit the same agent, each works on a separate draft and merges the others’ changes before publishing.
