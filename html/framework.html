Agent framework

An agent is just JSON, with Python expressions.

Here is a complete agent. It sends the user’s question to a language model and streams the answer back.

Every agent has the same shape.

An agent is a set of named functions, and a function is a list of commands that run in the order they are written. Each command is a key, and its value carries the command’s fields. A string value enclosed in braces is a Python expression; any other string is plain text. Where a command reaches outside the agent, to a model, an API or a database, it names a profile, and the profile holds the connection details. An llm command also names a prompt, which is set in the GUI and holds the text sent to the model.

Now give it an API to call

This agent answers questions about orders. It has a function that looks up an order through an API, and the model decides when to call that function. Agent files are JSONC, which is JSON that allows comments, so this one has a few.

Twenty commands are all you need

Every agent is written with these commands and nothing else. You concentrate on what the agent should do, and the framework takes care of everything around it.

Development process

Draft, validate, publish

An agent goes through three stages on its way to the users who will run it.

Draft

A draft is private to the developer who created it. You can write it in the editor, which knows the agent language and points out mistakes as you type, or let Draft with AI write the first version from a sentence and then refine it by hand.

Validate

Validation checks the definition against the schema and the security rules, and confirms that everything the agent refers to exists in the account. The agent server then runs the draft on a sample question and shows the trace: every command that ran, what it was called with, and what it returned. An agent cannot be published until validation passes.

Publish

When an agent is published, it receives a version number and a description written in plain English. Search indexes that description, and users find the agent by asking for what it does, in their own words.

Everything the agent did not spell out is handled by the controlled runtime: credentials, connections to outside systems, streaming, conversation memory, pausing for a person’s answer, and the time and cost limits that every run stays within.
