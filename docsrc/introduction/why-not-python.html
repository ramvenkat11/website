A fair question is why an agent is JSON with Python expressions, and not simply a Python program. A definition made of data can be generated, checked, read and governed in ways a program cannot.

AspectA Python programA Search2o agent
Writing itSomeone writes the code. An AI can write code too, but a plausible program and a correct program look alike.Draft with AI writes or edits the definition from a description. The schema says whether the result is a valid agent.
Before it runsSyntax is checked. The rest appears at runtime.The schema, every expression and every reference to a function or a profile are checked. A validation run must pass before publishing.
Reading itProgrammers can read the code.An agent is an ordered list of named commands. The people who own the process can follow the steps.
Trusting itA program reaches the file system, the network and the process. Holding a program back takes isolation outside the program.Expressions run in the controlled runtime. Only allowlisted names are reachable, and import is not available.
LimitsWhatever limits the author remembered.Run time, loop iterations, database rows and LLM spend are capped for every agent, by administrators.
Shipping a changePackage the code, install the dependencies, deploy and restart.Publish. Every agent server in the account runs the new version on its next run.
Measuring itWhatever the author chose to log.Every run carries its duration, its result and its LLM cost. The reports cover every agent.

Python does not disappear. Every expression in an agent is Python, so the full power of an expression is available where the power is needed.
