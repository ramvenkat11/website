Search2o Cloud

The cloud service holds all state: accounts and users, agent definitions and drafts, configuration, conversation context, the search index, and the data behind the reports. It checks agent definitions, indexes the description a developer writes for a published agent, and answers searches. Only agent servers call the cloud's API. The Search2o license prohibits calling it directly, because a direct call can leave data inconsistent.

The agent server

The agent server, with the bundled UI, is a Python 3.12+ package installed with pip install search2o. It runs inside your organization and holds no state. At startup it loads the account's configuration, keeps that configuration current, and runs agents. Its REST API is described at /openapi.json, with Swagger UI at /docs and ReDoc at /redoc.

The server is asynchronous and needs nothing beyond its Python packages. Run one on a laptop, run one as a standalone server, or run several as a load-balanced cluster. No server holds state, so any server can serve any request.

The UI

The UI is a single-page application bundled with the agent server and served at /ui. It uses only the agent server's REST API. What a person sees depends on their role. Users get search and conversations. Developers also get drafts, the editor with Draft with AI, validation and publishing, agent configuration and agent execution reports. Administrators also get users, authentication, system configuration and user reports. Owners get account settings and billing as well.
