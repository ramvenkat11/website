Search2o has three parts: a cloud service, an agent server that runs in your organization, and a GUI served by that agent server.

Search2o Cloud

The cloud service holds all state: accounts and users, agent definitions and drafts, configuration, conversation context, and the data behind the reports. The cloud checks agent definitions, indexes each agent's description, and answers searches. Only agent servers call the cloud's API; the API is not documented, and the license prohibits calling it directly.

The agent server

The agent server is a Python 3.12+ package, search2o, installed with pip. The server runs inside your organization and holds no state: at startup it loads the account's configuration, keeps that configuration current, and runs agents. Every call an agent makes leaves from the agent server: calls to your APIs, databases, LLM providers and MCP servers. Data and credentials therefore stay inside your boundary. The server's REST API is described at /openapi.json, with Swagger UI at /docs.

The server is asynchronous and needs nothing beyond its Python packages. Run one server on a laptop, run one as a standalone server, or run several as a load-balanced cluster. No server holds state, so any server can serve any request.

The GUI

The GUI is a single-page application bundled with the agent server and served at /ui. The GUI uses only the agent server's REST API. Each role sees what that role can do. Users get search and conversations. Developers get drafts, the code editor, AI assist, validation and publishing. Administrators get users, authentication, configuration and reports.
