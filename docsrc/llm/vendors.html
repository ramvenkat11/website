Search2o ships with six adapters: OpenAI, Anthropic and Google Gemini for the three vendors, and Ollama, vLLM and SGLang for models you host. One API key is enough to start, and a new account already has a profile for each of the three vendors.

The key

Each seeded profile reads its key from the agent server's environment. Set the key for the vendor you use before starting the agent server:

$ export OPENAI_API_KEY=... # OpenAI $ export ANTHROPIC_API_KEY=... # Anthropic $ export GEMINI_API_KEY=... # Google Gemini

Where a key is read from is configurable; see Secret vault.

The seeded profiles

A new account has these LLM profiles. An agent names one of them in its llm command.

The prices on a seeded profile are the list prices at the time the account was created. Please edit them to match your own contract, so that the cost report is right.

A profile for another model

A profile is one model at one vendor, so a second model needs a second profile. Create one under Profiles › LLM in the GUI and set:

FieldWhat to set
adapteropenai, anthropic or gemini, matching the protocol the endpoint speaks; ollama, vllm or sglang for a model served by one of those.
urlThe endpoint, for example https://api.openai.com.
headersAuthorization and anything else the vendor wants. The values are dynamic strings, so the key can be read at call time: { f"Bearer {sys.secret['OPENAI_API_KEY']}" }.
modelThe model name as the vendor writes it.
pricingThe prices per million tokens.

Every field is described in LLM profiles. An agent changes model by naming a different profile; nothing in the agent's code changes.

Models you host: Ollama, vLLM and SGLang

The ollama, vllm and sglang adapters connect to open models that run on your own hardware, served by Ollama, vLLM or SGLang. All three adapters call the server's OpenAI-compatible Responses API, at the path /v1/responses. Create a profile under Profiles › LLM and set:

FieldOllamavLLMSGLang
adapterollamavllmsglang
urlThe agent server's route to the model server, ending in /v1/responses. On the same machine with the default ports: http://localhost:11434/v1/responses for Ollama, http://localhost:8000/v1/responses for vLLM, http://localhost:30000/v1/responses for SGLang.
headersContent-Type alone when the server asks for no key.
modelThe model as Ollama names it, for example qwen2.5:7b.The name the model is served under.

Ollama does not act on a forced tool choice. When an llm command sets outputFormat: "structured", the ollama adapter asks Ollama for JSON that fits the schemas of the offered functions and turns the reply into function calls, so the command returns the same dict as with any other adapter.

vLLM makes tool calls only when the server is started with tool calling switched on: --enable-auto-tool-choice and the --tool-call-parser that fits the model. SGLang makes tool calls only when it is started with the --tool-call-parser that fits the model.

Any compatible LLM

The openai, anthropic and gemini adapters are not limited to those three vendors. Any endpoint that speaks one of the three protocols works with the matching adapter and a profile that points at the endpoint's URL — a private deployment, a gateway, or another vendor's compatible API. See Connecting to other LLMs.
