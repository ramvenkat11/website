A browser signs in with login and receives a session cookie. A script signs in with scriptLogin and receives a bearer token. Every later call carries one or the other.

Session cookie

POST /api/auth/login with email and password. The response sets an HTTP-only cookie, and the browser sends the cookie on every later call. A session ends after a period of inactivity and after a maximum lifetime; both are set in the Authentication configuration. POST /api/user/logout ends the session.

Bearer token

POST /api/auth/scriptLogin with the same email and password. The response carries the token, the token type and the number of seconds until the token expires:

$ curl -s -X POST http://127.0.0.1:9020/api/auth/scriptLogin \ -H "Content-Type: application/json" \ -d '{"email": "bot@example.com", "password": "..."}' {"success": true, "token": "…", "tokenType": "Bearer", "expiresIn": 3600}

Send the token in the Authorization header of every later call:

$ curl -s -X POST http://127.0.0.1:9020/api/user/getUserProfile \ -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}'

A token lasts one hour by default; the lifetime is the script token max age in the Authentication configuration. A script that runs longer than the token signs in again when a response carries mustLogin: true.

Which user to sign in as

A script runs as the user whose credentials it holds, with that user's role. Conversations, memories and the usage report are recorded against that user. Create a dedicated user for each integration, so that the reports show what the integration did and so that the credentials can be revoked on their own.

Password reset

emailCode sends a one-time code to the user's email address, and createPasswordWithEmailCode sets a new password with that code. A reset signs out every session of the user. The password rules are available from getPasswordHelp, so a client can show them before the user types.
