Runs several of the agent's functions at the same time and returns their results as a dict, with one entry per call.

Shape

parallel is shaped like var, not like a command block. Each key names a function to call. Each value is an object holding the arguments for that call; the object is empty when the function takes no arguments. To call the same function twice, add a suffix after a dot, as with repeated commands: lookup and lookup.2. The result is a dict with the same keys. At least one function must be named, and main cannot be one of them.

Example

"parallel": { "fetchWeather": { "city": "{ city }" }, "fetchEvents": { "city": "{ city }" } }, "var": { "weather": "{ result['fetchWeather'] }", "events": "{ result['fetchEvents'] }" }

Rules

  • The result is keyed by the names used in the command, so the order in which the calls finish does not matter.
  • Each function runs in its own scope with its own locals. Agent and conversation variables are shared, so two parallel functions should not write the same variable.
  • A function that runs in parallel may ask, may call a function that asks, and may invoke an agent that asks; see below.
  • If any call fails, the whole command fails with that error. onError on the calling function can handle the error.

Asking from a branch

A branch may pause on ask, at any depth: in the function itself, in a function it calls, or in an agent it invokes. parallel waits until every branch has either finished or paused. Then the questions of every paused branch are sent to the user together, one form per branch, each keyed by the branch's name in the command, such as lookup and lookup.2. When the user answers, the command runs again: the branches that had finished keep their results and do not run again, and each paused branch resumes at its own ask with its own answers. A branch whose answers have not arrived asks again, so the user may answer one form at a time. A branch that runs a parallel command of its own nests its branches' forms under its key.

This is what lets an orchestrator run several agents at once, whether or not any of them stops to ask. How the questions reach a client of your own is on Running agents.
