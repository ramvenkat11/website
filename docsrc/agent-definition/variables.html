There are three kinds of variables, with three scopes: local, agent and conversation. The runtime also provides a few read-only names.

Local variables

Local variables are set and read without a prefix. A local variable lives in the function that set it and disappears when that function returns. Function arguments and for loop variables are locals. A local variable can hold any Python value.

Agent variables

Agent variables are written agent.name. An agent variable lives for the whole conversation. Every function of the agent can read and write it; other agents cannot. Use agent variables for state that a follow-up query should find again: whether initialization has run, a cached lookup, the user's last choice.

Conversation variables

Conversation variables are written conv.name. A conversation variable lives for the whole conversation, and any agent that runs in the conversation can read and write it. This is how agents hand work to each other: one agent leaves a result in conv.order, and the next agent picks it up.

Agent and conversation variables are saved with the conversation, so their values must be JSON serializable. Reading a variable that has never been set raises an error. sys.exists(scope, name) answers whether the variable exists first, so a variable can be seeded on first use: "{ (agent.count if sys.exists('agent', 'count') else 0) + 1 }".

Setting variables

The var command sets variables of all three kinds. It can also set one element of an existing list or dict: "totals['q3']": "{ ... }". Once set, a variable can be read in any dynamic string.

Validation refuses an expression that reads a local variable nothing before it can have set, and a prompt that does the same; see Python expressions.

Read-only namespaces

const

const holds the agent's constants: a JSON object set in the GUI with the draft, like the prompts, and read as const.name. The object is encrypted on its way to and from Search2o Cloud, so the cloud never reads it. An agent cannot assign to const. Validation lists the keys the agent reads, and the agent server checks that the agent's const has them.

sys

The runtime provides sys. These names are always present:

  • sys.inputs: the inputs the agent was started with, as a dict. For a search the dict is { "query": ... }. A call to execAgent passes any inputs it likes.
  • sys.query: the user's query, the same as sys.inputs['query'].
  • sys.secret[name]: reads a secret by name. Where secrets come from, the environment, a file or your own vault, is on Secret vault.
  • sys.exists(scope, name): whether a variable exists, before reading it. The scope is local, agent, conv, const or allowlist; see Python expressions.

These names are present only when an administrator enables them in the system variables configuration:

  • sys.userEmail: the email address of the user running the agent.
  • sys.userSession: a hash of the user's session, for keying per-session data.
  • sys.serverIp: the agent server's address as seen by the cloud, for logging.
  • sys.cookies: the cookies of the request that started the run.

command

command holds the values of the current command's fields evaluated so far. A field may refer to a field written earlier in the same command as command.field.

Other names

  • result: the result of the most recent command that produces one.
  • exc: inside an onError block, the exception being handled.

sys, command, result, exc, agent, conv, const and onError are reserved and cannot be assigned, nor used as argument or loop variable names. Python keywords cannot be variable names either.
