A prompt is what an llm command sends to a model: a system text, a user text, and the history of the exchange so far. An agent's prompts are set in the GUI, like its title and run limits, not written in the definition. Each prompt has a name, and an llm command names the prompt it uses in its prompt field.

For example, an agent that answers questions about orders could have this prompt:

Nameorders
SystemYou answer questions about orders. Answer in under 100 words.
User{ sys.query }
Scopeconversation
DocAnswers questions about orders, with the getOrder tool.

The agent's llm command names it:

"llm": { "profile": "gpt5_mini", "prompt": "orders", "streamOutput": true }

Fields

A prompt needs a system text, a user text, or both. A prompt name is letters, digits and underscores. An agent may have up to 10 prompts, and each text up to 20,000 characters.

Where prompts are edited

In the GUI, an agent's prompts are listed under Prompts on the draft page. Add prompt adds one. Prompts change only through a draft: edit them there, validate, and publish. Validation compiles each prompt with the draft, so a prompt that reads a variable the agent never sets, or reads result, is refused before it can run.

A publish that changes only the prompts does not make a new version of the agent. The agent's next run uses the new text. A prompt that an llm command names cannot be dropped: remove the command's use of it in the same draft. Publishing records which prompts were added, removed or changed in the audit log, by name, never their text.

When the published agent's prompts, title or run limits changed after the draft was made from it, publishing the draft shows which of them differ. Publishing again replaces them with the draft's values. See Publishing.

How a prompt is evaluated

The system and user text are written like any other string in an agent: plain text, or a Python expression in braces. Both are evaluated each time an llm command that names the prompt runs, in the function where that command runs, so they can read the function's arguments and local variables, as well as agent., conv., const. and sys. names.

A prompt cannot read result. To give the model what a command fetched, set a variable from result before the llm command:

"api": { "profile": "orders", "path": "{ f'/orders/{orderId}' }" }, "var": { "order": "{ result }" }, "llm": { "profile": "gpt5_mini", "prompt": "summary" }

The prompt named summary then reads the variable in its user text:

Namesummary
SystemYou write short, friendly summaries of orders for customers.
User{ f'Summarize this order: {order}' }
Scopelocal

Each time the llm command runs, the evaluated system text replaces the prompt's system text, and a non-empty user text is added to the prompt's history. The model's answer, and any tool calls and tool results, are added to the history too, so the next llm call with the same prompt carries the whole exchange. The trace shows each call's prompt name, scope, system text and user text as an input.

Scope

The scope decides how long a prompt's history is kept and which agents share it.

ScopeHistory
conversationThe default. One history for the whole conversation, shared with every other agent in the conversation that has a prompt of the same name and scope.
agentThis agent's own history in the conversation. Other agents in the conversation do not see it.
localA history for one run only. It is kept while the run pauses on an ask, and it is empty when the next run starts.

An agent may have several prompts, and each keeps its own history. A second prompt suits a separate exchange beside the main one, such as a step that classifies the request. Give a prompt like that the local scope, so that its history does not grow from one run to the next.

Sharing a history between agents

A conversation can move from one agent to another, as it does when a follow-up search matches a different agent. The second agent continues the first agent's exchange only when both agents have a prompt with the same name and the conversation scope. A prompt with another name starts with an empty history. The history is kept in a form that does not depend on the model, so the second agent may use a different LLM.

Agents meant to work together in one conversation should therefore agree on a prompt name. When the second agent's prompt has a system text, that text replaces the first agent's at the second agent's first llm call, so each agent gives the model its own instructions.

Images

The user text may also be an expression that produces a content part, or a list of content parts. An image reaches a vision model as a content part. This user text sends a photo from the agent's inputs with a question:

{ [ {'contentType': 'image', 'contentBase64': sys.inputs['photo'], 'mimeType': 'image/png'}, {'contentType': 'text', 'text': 'What is in this picture?'} ] }

Documentation

The doc field is plain text that says what the prompt is for. Draft with AI sees each prompt's name and doc, never its text, so a useful doc helps the AI choose the right prompt for each llm command.
