When several developers create drafts of the same published agent, each developer works on an independent copy. Publishing reconciles the copies.

How it works

A draft remembers the version of the agent the draft was created from. If the agent has been republished since, publishing the draft opens a merge view in the GUI. The merge view shows three definitions with the differences highlighted: the version the draft started from, the current published version, and the draft. Conflicts are resolved in the merged definition. The merged definition is then validated and published like any draft.

The process is similar to a source-code merge in systems such as GitHub. If the agent has not changed since the draft was created, publishing needs no merge.

Practical advice

  • Keep drafts short-lived. The longer a draft waits, the more likely a merge becomes.
  • Check the published agent's history before starting a large change.
  • Move shared prompt text into prompt profiles, so that wording changes never need a merge.
