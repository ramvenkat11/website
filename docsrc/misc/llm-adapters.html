An LLM that speaks the OpenAI, Gemini or Anthropic protocol needs only an LLM profile that points at its URL. An LLM with a different interface needs an adapter class. You write the adapter in Python and register it through the allowlist.

Compatible LLMs

Create a new LLM profile in the GUI, pick the adapter that matches the protocol (openai, anthropic or gemini), and set the URL, the headers and the model. Private deployments and gateways that expose one of these protocols need nothing more.

Writing an adapter

An adapter turns the request that Search2o builds (prompt, tools, model and limits) into the vendor's request format, and turns the vendor's response back into Search2o's form. Subclass one of two classes from the search2o package:

  • search2o.llm.basellmadapter.BaseLlmAdapter does the assembly and asks you only for the vendor-specific pieces: how to set the model and the token limit, how to express tools, the system prompt and each kind of message, and how to read flags and token counts from the response. BaseLlmAdapter is the right base for most APIs.
  • search2o.llm.llmadapter.LlmAdapter is the bare interface: name, description, process_request, process_response and get_error. Use this class for a protocol so different that the base class does not help.

The bundled adapters in search2o.llm are the reference implementations, and their source is available.

Registering it

  1. Put the class in the Python environment that the agent server runs in.
  2. Add the class to the allowlist as mypackage.myadapter.MyAdapter and save.
  3. The agent server instantiates every allowlisted subclass of LlmAdapter when the server loads the allowlist, and lists those adapters under Adapters when a new LLM profile is created. An adapter whose constructor fails is reported on the Agent servers page.

The class needs a constructor that takes no arguments. Reports group spend under the profile's vendor field, so set that field to the vendor's name, whatever the adapter is called.
