The rest of the runtime is what agents connect through and refer to: the connection pools, the profiles, and the secrets and encryption settings. Each reaches every agent server the same way as the guardrails, before the server's next run.

Connection pools

Many parts of the agent servers need to connect to a HTTP service: Connection to the Search2o cloud, LLM servers and api commands/profiles. They can all use different connection pool settings. These are defined in the connection pools page in the GUI. A connection pool called 'default' is used when no other connection pool is defined.

Profiles

The runtime holds every profile of the account: LLM profiles with their open connections, prompt profiles, API profiles, database profiles with their open connection pools, and MCP servers. When a profile changes, the runtime rebuilds only what depends on that kind of profile. A changed LLM profile reopens the LLM connections. A changed database profile builds a new database engine, and the old engine closes once the last agent using the old engine finishes. A changed prompt or API profile is simply replaced. What each kind of profile holds and the rules that apply to profiles are in the Profiles section.

Secrets and encryption

The runtime also carries the secrets source, the decrypted hosted secrets when that source is in use, and the encryption settings with the key function for end-to-end encryption. Both are edited under Operations › Secrets & encryption and are explained in The secret vault and Encryption.
