Three parts of the runtime bound what an agent's expressions may do: the allowlist, the compile rules and the runtime limits. The GUI groups them under Guardrails, and developers edit them. Why they exist and what they protect against is explained in The controlled runtime; this page covers how each is written and how the runtime applies it.

Allowlist

The allowlist is the complete set of functions and objects an expression may reach. When the allowlist changes, the runtime imports each entry from the server's Python environment and builds the namespace that expressions evaluate in. An entry that cannot be imported is written to the server's log.

One entry per line; anything after # is a comment.

len # a builtin str.join # a method of a builtin type math.sqrt as sqrt # a module attribute, under an alias datetime.datetime as datetime # a class; its public members become available json.loads # callable as json.loads(...), not loads(...) mycompany.vault.get_secret # anything importable in the server's environment

Expressions use an entry's full dotted name unless the entry is aliased with as. A package your agents need is installed next to search2o. Expressions run on the server's shared event loop, so a function that blocks the loop must not be allowlisted. asyncio.run and synchronous network calls are examples, and the asyncio package itself is refused. gather and sleep are always available. A coroutine on the allowlist is awaited only when the coroutine is the whole expression.

The allowlist is also where custom code is registered: an LLM adapter, the key function for end-to-end encryption, or a function that reads your own vault. sysVariables lists which of userEmail, userSession and serverIp agents may read from sys.

Compile rules

Each of the operators + - * / // % ** << >> @ is set to allow, deny or rewrite. The rules are applied when a draft is validated or published, so a change reaches a published agent only when that agent is republished. A denied operator fails validation with the path of the expression. A rewritten operator is replaced by a call to a safe function that bounds the operation; the built-in functions live in search2o/execution/safeoperators.py, and safe_pow, for example, refuses exponents above 64. To substitute your own safe function, allowlist a function under the same name. Comprehensions are bounded by nesting depth and by the number of for clauses.

Runtime limits

The limits are checked while the agent runs. Elapsed time is checked between commands, and inside loops every yield loops after iterations. A run past the limit ends with the result code timedOut. A long LLM or API call in progress ends only when the call's own timeout fires. A loop that exceeds the iteration limit fails the run. A db command returns at most the row limit. The LLM cost limit is checked after each call, against the prices in the LLM profile; a profile with no prices never trips the limit. The definition length applies to the JSONC text of a draft, comments included. The stream heartbeat sets how often a streamed response sends a keep-alive line.
