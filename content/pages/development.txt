# An agent framework built for AI-assisted development

Tactet has its own agent framework. An agent is a JSON document with one structure and 20 commands, and its values can be Python expressions. One schema describes all of it. Draft with AI, the code editor and validation work from that schema, in the development environment that is part of the UI.

Agent framework


## An agent is JSON with Python expressions

Below is a complete agent. It searches a knowledge base for the user’s request and has a model write the answer from the best passages.

[figure: A complete agent with five notes]

Every value keeps its JSON meaning, with one extension: a string enclosed in braces is a Python expression, evaluated when the agent runs. Any other string is plain text. An expression can read variables, the result of the last command, and what the runtime provides, such as the user’s request. Each expression is checked when the agent is validated and runs in a controlled runtime.


## Every agent has the same structure

An agent is a set of functions. Each function contains an ordered map of commands. The commands run in the order in which they are declared.

[figure: The structure of an agent and the 20 commands]

A command is a key, and its value contains the command’s fields: an object for most commands, and a single value for simple ones such as progress and return. To use a command a second time in the same function, add a suffix after a dot: api, then api.2. The syntax and structure pages explain all the rules.

Every run starts in main. Another function runs when a function calls it with func or parallel, or when a model calls it as a tool.


## A function can be a tool for the model

This agent answers questions about orders. Its function getOrder looks up one order through an API, and the model decides when to call it. Agents are written in JSONC, a form of JSON that allows comments, so this one includes a few.

[figure: An agent with a tool, with six notes]


## Systems and prompts are defined outside the agent

An agent names the systems it calls and the prompts it sends. The connection details are in platform-wide profiles, and the text of each prompt is in the agent’s meta. This agent lists a user’s open IT tickets and has a model say where each one stands.

[figure: A complete agent beside the three things it names]

A profile is shared by every agent that names it. A secret is read from the vault by name, so its value appears in neither the profile nor the agent. A prompt’s system and user text are written like any other string: plain text, or a Python expression that reads the agent’s variables.

The agent runtime handles everything the agent does not specify: credentials, connections to outside systems, streaming, conversation memory, pauses for a person’s answer, and the time and cost limits for every run.

Development environment


## Draft, edit, validate, publish

The UI includes a complete development environment for agents. An agent goes through four steps before users can run it.


## Draft with AI

Draft with AI writes the first version of an agent from a description of what the agent should do. It works from the same schema that the editor and validation use, and it knows the profiles and prompts of your account. It has never seen your APIs and databases, so it leaves paths, queries and parameters empty, with a comment that says what belongs there. It can also change an existing draft, and it keeps everything your request does not touch.

Try the Draft with AI demo with your own description or one of the examples.


## Edit

A draft is private to the developer who created it. The code editor is built on Monaco, the editor inside Visual Studio Code, and it understands the agent language. It suggests the commands and fields allowed where you are typing, and it points out mistakes as you type.


## Validate

Validation checks the definition against the schema and the security rules. It also confirms that everything the agent names exists in the account. The agent server then runs the draft against a sample question and shows the trace: every command that ran, the values it received, and what it returned. A draft cannot be published until it validates.

The Trace demo shows a trace of a running agent.


## Publish

Publishing gives the agent a version and makes it available to users. The developer then describes the agent in plain English. Search indexes that description, and users find the agent by asking for what it does in their own words. When several developers change the same agent, each works on a separate draft and merges the others’ changes before publishing.
